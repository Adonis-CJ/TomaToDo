## 2. 背景与目标

### 2.1 现状与问题

| # | 现状（v1.1.1） | 问题 |
|---|---|---|
| P1 | 卡片 = Room 行内的 `front` / `back` 两段纯文本 | 无法承载结构化笔记：无标题层级、无列表、无表格、无代码块；数学公式只能打成纯文本 |
| P2 | 图片独立存 `card_images` 表，与正文割裂 | 正文无法决定图片位置，导出后图文分离 |
| P3 | 列表卡片直接展示全文（`maxLines = 4`） | 卡片一多就是文字墙，无法快速扫读定位 |
| P4 | 删除即真删（`DELETE` + 物理图片删除） | 无任何防误删保护，整理卡片时风险高 |
| P5 | 标签为 JSON 文本列 | 无法按标签聚合筛选、无法重命名/合并 |
| P6 | 撰写页是 front/back 表单 | 与「知识管理」定位不符：用户要写的是一篇笔记，不是填两张表单 |

### 2.2 升级目标

1. **卡片即文档**：每张卡片是一份独立、自包含的 Markdown 文档（含图片），可用任意编辑器打开。
2. **看得舒服**：MD + LaTeX + 代码高亮全渲染；列表只给摘要，点开是阅读/编辑双视角。
3. **删得安心**：所有删除先进回收站，30 天后才真正清除。
4. **归类省力**：标签体系 + 科目 + 类型组合筛选，全文搜索直达。
5. **为复习服务**：文档结构直接服务于遗忘曲线复习（问面/答面），复习时渲染公式与图片。

## 3. 总体设计

### 3.1 核心原则：文件为源，数据库为索引

```
┌─────────────────────────────────────────────────────────┐
│                      知识卡片（KMS）                       │
│                                                         │
│   filesDir/cards/{cardId}/            Room（索引层）      │
│   ├── note.md          ←—— 源内容 ———→  title/excerpt/    │
│   │                                     wordCount/deletedAt │
│   └── assets/          ←—— 引用 ———→   派生字段，仅供列表    │
│       └── *.jpg                          展示与检索加速     │
└─────────────────────────────────────────────────────────┘
        唯一写入口：CardRepository（写文件 → 更新索引，同一事务语义）
```

- **`note.md` 是唯一事实源（source of truth）**。Room 只存元数据与派生摘要（`excerpt`、`wordCount`），保证列表滚动与搜索不读文件。
- 所有写操作收敛到 `CardRepository`：保存卡片 = 原子写 `note.md`（先写临时文件再 rename）→ 更新 Room 行。杜绝「索引与文件不一致」。
- **决策记录**：内容不存 Room TEXT 列 —— 用户要求卡片是独立 md 文档；文件化才能支持「导出即 Obsidian 笔记库」与图片相对路径引用。

### 3.2 存储布局

```
filesDir/
├── cards/
│   ├── {cardId}/
│   │   ├── note.md                    # 卡片正文（MD）
│   │   └── assets/                    # 该卡片的图片（相对路径引用）
│   │       ├── 20260828_143022.jpg
│   │       └── ...
│   └── ...
├── images/                            # v1 旧图目录（迁移后清空，保留兼容）
└── backups/
```

图片在 `note.md` 中以相对路径引用：`![错因截图](assets/20260828_143022.jpg)`。渲染器把相对路径解析到 `cards/{cardId}/assets/`。

## 4. 功能设计

### F-A 卡片即文档（MD 存储）——P0

**用户故事**：作为考研学生，我希望每张卡片是一篇真正的 Markdown 笔记，标题、公式、代码、图片混排。

**功能点**

- 新建/编辑后的卡片内容保存为 `cards/{id}/note.md`；`title` 取首个 `# ` 一级标题，无标题时取首行非空文本（截断 50 字符）。
- 卡片继承原元数据：科目、类型（错题/知识点）、来源、掌握度、复习排程字段全部保留。
- 正文中的图片由插入功能生成相对路径引用，随卡片目录一起备份/导出。
- 旧 `card_images` 表职责合并进 md 内引用（见 §6 迁移）。

**验收标准（AC）**

- [ ] 每张卡片对应一个 `note.md`，可用文本编辑器直接打开阅读。
- [ ] 卡片内图片存于同目录 `assets/`，md 内相对路径引用，删除卡片时整目录一并清理。
- [ ] 列表页展示不触发文件读取（excerpt 来自索引）。

### F-B Markdown + LaTeX 渲染 ——P0

**用户故事**：作为考研学生，我希望卡片里的数学公式、表格、代码块都被正确渲染，像一篇排版好的笔记。

**功能点**

- MD 能力：标题、加粗/斜体/删除线、有序/无序列表、任务列表、引用、表格、分隔线、行内/块级代码、链接、图片。
- **LaTeX 公式**：行内 `$...$`、块级 `$$...$$` 双语法；支持考研数学常用结构（分数、上下标、根号、矩阵 `bmatrix`、求和/积分/极限、多行对齐 `aligned`）。
- **代码高亮**：Prism4j，覆盖 C / C++ / Java（408 算法题场景）。
- 渲染主题跟随「墨·纸」设计令牌（浅/深色两套），公式与正文字号一致。
- 渲染性能：解析在 IO 线程完成；阅读视图按需渲染；列表摘要永不渲染。

**验收标准（AC）**

- [ ] `$E=mc^2$` 与 `$$\int_a^b f(x)\,dx$$` 在阅读视图正确渲染。
- [ ] 表格、代码块（含高亮）、任务列表正确渲染。
- [ ] md 内相对路径图片正确显示，点击进入全屏图片查看器（复用现有 `ImageViewer`）。
- [ ] 深色模式下公式、代码块配色可读。

### F-C 阅读视图 / 编辑视图 ——P0

**用户故事**：作为考研学生，我希望列表卡片只显示摘要，点开后默认进入舒适的阅读态，一键切换到编辑态。

**功能点**

- **列表项瘦身**：科目色点 + 类型角标 + 标题 + 摘要（`excerpt`，≤2 行）+ 标签 + 复习状态徽标（待复习 N 天）+ 图片数量角标。不再展示 4 行全文。
- **打开卡片 → 阅读视图（默认）**：全宽渲染正文；顶栏含「编辑」「标签」「科目」「删除」「返回」；底部信息条：来源 / 掌握度 / 复习次数 / 更新时间。
- **切换编辑视图**：顶栏 `编辑` 按钮（阅读 ↔ 编辑双向切换，保留滚动位置附近的上下文）。
  - 编辑器 = 多行纯文本框 + **插入工具栏**（加粗、标题、列表、表格、代码块、引用、链接、图片、公式、`[[]]` 链接）。
  - **图片插入**：拍照 / 相册（复用现有 CameraX + Photo Picker 流程），压缩落盘到 `assets/` 后在光标处插入 `![](assets/xxx.jpg)`。
  - **公式插入**：常用结构快捷片（分数、根号、矩阵、求和等，见 F-K5）。
  - 平板横屏：左侧编辑、右侧实时预览分栏；窄屏：工具栏「预览」按钮切换。
- **保存策略**：停止输入 1.5s 防抖自动保存 + 退出视图即保存；保存成功顶栏轻提示（无需手动保存按钮）。
- 旧「撰写页」（`CardEditScreen` 表单流）被编辑视图取代：front/back 表单退场。

**验收标准（AC）**

- [ ] 列表项 ≤2 行摘要 + 元信息，无文字墙。
- [ ] 打开卡片默认阅读视图，渲染正确；一键进入编辑视图并回显原文。
- [ ] 编辑中拍照/选图后光标处自动插入图片引用，保存后阅读视图可见。
- [ ] 横屏分栏实时预览，改一个字预览即刷新。
- [ ] 编辑过程中杀进程，重开后内容不丢（防抖落盘）。

### F-D 标签系统 ——P0

**用户故事**：作为考研学生，我希望能按「动态规划」「页表置换」这类知识点维度归组和检索卡片。

**功能点**

- 标签升级为独立表 `tags` + 关联表 `card_tags`（替代 JSON 列，见 §6），支持计数、筛选、重命名级联。
- 编辑视图内标签输入：输入即联想已有标签（自动补全），回车建新标签；标签可多选。
- 列表页筛选升级为**筛选抽屉**：科目（保留现有 Chip 行）+ 标签（多选）+ 类型（错题/知识点）+ 复习状态（待复习/已掌握），组合过滤。
- **标签管理页**（P1，入口在筛选抽屉）：重命名（级联更新）、合并、删除（同时解除关联）。
- 通用标签小圆片样式：4dp 圆角、浅描边、`line` 色边框，符合设计令牌。

**验收标准（AC）**

- [ ] 可给卡片打多个标签，列表按标签筛选（多选取交集）。
- [ ] 重命名标签后所有关联卡片自动生效；删除标签不删卡片。
- [ ] 旧 JSON 标签无损迁移为标签表数据。

### F-E 回收站 ——P0

**用户故事**：作为考研学生，我整理卡片时手滑删掉重要笔记，希望能找回。

**功能点**

- **软删除**：删除 = `knowledge_cards.deletedAt` 置时间戳 + Snackbar「已移入回收站 · 撤销」；物理文件（`note.md`、`assets/`）**原地保留**，不搬目录（避免恢复时的冲突与 IO，标记法即可）。
- 所有正常视图（列表/搜索/筛选/复习队列/统计）查询统一过滤 `deletedAt IS NULL`。
- **回收站页**：卡片页顶栏入口，列表显示 标题/所属科目/删除时间；支持单项「恢复」「彻底删除」与「清空回收站」（二次确认）。
- **自动清理**：删除满 30 天后自动彻底删除（卡片模块加载时惰性扫描执行，不引入 WorkManager）。
- 彻底删除 = 删除 Room 行（级联 `card_tags`、`review_records`）+ 删除 `cards/{id}/` 目录。
- 复习排程字段保留：恢复后卡片回到原复习队列，`nextReviewAt` 已过期的自然进入今日待复习。

**验收标准（AC）**

- [ ] 删除卡片后列表消失、回收站出现，Snackbar 撤销可还原。
- [ ] 回收站内可恢复与彻底删除；清空需二次确认。
- [ ] 删除满 30 天的卡片在下次启动后被自动清除。
- [ ] 处于回收站的卡片不出现在复习队列、搜索结果与统计中。

### F-K1 全文搜索 ——P1（补充）

**用户故事**：卡片多了以后，我希望直接搜「LRU」或「贝叶斯公式」一步定位到卡片。

**功能点**

- 中文分词限制与兜底见 §10 风险 R3。

**验收标准（AC）**

- [ ] 英文关键词（LRU、TCP）秒级命中。
- [ ] 中文关键词可命中（含 LIKE 兜底路径），命中词高亮。
- [ ] 回收站内卡片不参与搜索。

### F-K2 卡片双链 ——P2（补充）

**用户故事**：复习「页面置换算法」时，我希望直接跳到关联的「队列」「时间局部性」卡片，织成知识网。

**功能点**

- 正文支持 `[[卡片标题]]` 链接，阅读视图渲染为可点击链接，跳转到对应卡片。
- 编辑工具栏一键插入 `[[`；输入时联想卡片标题。
- 阅读视图底部显示**反向链接**（哪些卡片引用了本卡），点击可跳转。
- 标题 → id 的解析基于 Room 索引（title 列唯一性不强制，重名时跳转第一个匹配并在链接下标注歧义）。

**验收标准（AC）**

- [ ] `[[标题]]` 渲染为链接样式，点击跳转对应卡片阅读视图。
- [ ] 被引用卡片底部列出全部反向链接。
- [ ] 目标卡片在回收站时链接置灰不可点。

### F-K3 复习模式适配 ——P1（补充）

**用户故事**：复习时先回忆「这页笔记讲什么」，再展开全文自检，公式和截图都要能看。

**功能点**

- **问面/答面约定**：卡片正文首个 `---` 分隔线之前为「问面」（问题/知识点名/自检提示），之后为「答面」（详解/正解/延伸）。无分隔线时问面 = 标题 + excerpt。
- 复习页（`ReviewScreen`）单卡流程不变（忘记/模糊/记得），卡片内容改为：先渲染问面（MD 渲染），「查看答案」后展开答面全文（含公式与图片）。
- 艾宾浩斯排程逻辑（`ReviewLogic`）零改动。
- 迁移：v2 卡片的 `front` 映射为问面、`back` 映射为答面，中间自动补 `---`（见 §6）。

**验收标准（AC）**

- [ ] 复习页正确只显示问面，查看答案后展示答面（公式/图片渲染正确）。
- [ ] 问面/答面拆分规则对旧迁移卡片与新卡片一致。
- [ ] 复习记录与排程行为与 v1.1.1 完全一致。

### F-K4 导入导出与备份 ——P1（补充）

**功能点**

- **全量 ZIP 备份扩展**（`BackupManager`）：`backup.json` + `images/`（旧）+ `cards/`（新，含各卡片目录）。导入按目录结构原样还原，与现有导入逻辑并存。
- **MD 笔记库导出**（P2）：把 `cards/` 导出为标准笔记库 ZIP —— 每卡一个 `.md`（图片放同级 `assets/`），元数据写入 md 头部 YAML front-matter（`subject` / `tags` / `type` / `source`），可直接导入 Obsidian / Typora。
- **MD 导入**（P2）：选择符合该结构的 ZIP，批量建卡（front-matter 解析科目/标签）。

**验收标准（AC）**

- [ ] 备份-恢复后卡片正文、图片、标签、复习排程完整。
- [ ] 导出的笔记库 ZIP 在 Obsidian 中打开：每卡一篇笔记、图片可显示、标签可见。

### F-K5 新建模板与公式工具栏 ——P2（补充）

- 新建卡片时选择模板（可设置默认不弹选）。

**验收标准（AC）**

- [ ] 三种模板一键生成骨架；公式快捷片插入光标位置并自动定位待填参数。

## 6. 数据模型与迁移

### 6.1 Room schema v2 → v3

```kotlin
// v3：knowledge_cards 重建（SQLite 3.18 不支持 DROP/部分 ALTER）
@Entity(tableName = "knowledge_cards")
data class KnowledgeCard(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,                  // 新：首个 # 或首行截断
    val excerpt: String,                // 新：去语法纯文本摘要（列表用）
    val wordCount: Int,                 // 新：字符数
    val mdPath: String,                 // 新：相对路径 cards/{id}/note.md
```

### 6.2 v1.1.1 → v1.2 数据迁移（一次性，幂等可重跑）

迁移放在 `DatabaseMigrations.MIGRATION_2_3`（表结构）+ 应用启动时文件迁移器（文件落盘），二者以 `knowledge_cards` 行为对账基准：

1. **启动前自动保险**：迁移器首次执行前把 `cards/`、数据库文件快照备份到 `backups/pre_v1.2/`。
2. **标签**：解析每行 `tags` JSON → `INSERT INTO tags`（去重）→ 写 `card_tags`。
3. **正文文件化**（逐卡）：
   ```
   # {front 首行截断为标题}
   {front 其余}

   ---

   {back}

   ## 附图
   ![图1](assets/img_1.jpg)
   ```
   旧 `images/{uuid}.jpg` 复制为 `cards/{id}/assets/img_{n}.jpg`（复制而非移动，失败可重跑）。
4. **索引回填**：计算 title/excerpt/wordCount 写回行；`front/back/tags` 列随表重建移除。
5. **FTS 建索引**：重建 cards_fts 并全量灌入。
6. **孤儿清理**：无对应 Room 行的 `cards/{id}/` 目录移入 `.orphans/`（不直接删）。

**验收标准**：迁移后随机抽检 20 张卡片：正文/图片/标签/复习排程与迁移前一致；中断重跑无重复数据；迁移失败可回退（恢复 pre_v1.2 快照）。

### 6.3 查询层变化

- 所有既有 DAO 查询追加 `WHERE deletedAt IS NULL`（含 `observeAll`、`observeDue`、统计相关）。
- 新增 `TrashDao`（回收站列表/恢复/彻底删除/过期清理）、`TagDao`（联想/计数/级联重命名）、`CardsFtsDao`（搜索）。

## 7. 技术选型

| 项 | 选型 | 说明 |
|---|---|---|
| MD 渲染 | **Markwon 4.6.2**（`io.noties.markwon`）+ AndroidView 包 TextView | Android 生态最成熟的 MD 渲染器，插件化（tables/tasklist/latex/syntax-highlight/linkify），深浅主题可注入；虽已停止更新但 API 稳定、离线无依赖 |
| LaTeX | Markwon `ext-latex`（内置 JLatexMath） | 支持行内/块级，矩阵与 align 等考研数学结构完备，离线渲染 |
| 代码高亮 | Markwon `syntax-highlight` + Prism4j | C/C++/Java 语法集，按需裁剪体积 |
| 图片加载 | 复用 Coil（自定义相对路径解析器） | 与现有图片体系一致，缓存免费 |
| 全文搜索 | Room FTS | 与 schema 同源管理，触发器同步 |
| 备选记录 | compose-richtext + KaTeX（Jeluchu/compose-latex） | Compose 原生但 LaTeX 能力弱、表格/任务列表支持不全，弃 |

新增依赖预计增大 APK 约 1.5–2MB（JLatexMath 字体为主），相对当前 36MB 可接受。

## 9. 非功能需求

- **性能**：列表滚动零文件 IO；阅读视图 5000 字 + 10 图卡片打开 < 800ms（中端平板）；编辑防抖落盘不卡输入。
- **数据安全**：迁移前自动快照；文件写入原子（temp + rename）；备份兼容旧 ZIP（无 `cards/` 时按 v1.1.1 路径导入）。
- **体积**：新增依赖 ≤ 2MB；不做字体子集化（维持 Roadmap 独立项）。
- **一致性**：启动时低频校验（索引有行无文件 → 标记缺失并提示重建；有文件无行 → 进 `.orphans/`）。
